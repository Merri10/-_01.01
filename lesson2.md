# Ведение С++
## Язык программипрвания С++
Язык программирования С++ представляет высоко уровневый компелируемый язык програм общего назначения со статической типизацией.
Компилируемый язык — это язык, исходный код которого преобразуется компилятором в машинный код
Динамически - это прилагательное, которое имеет несколько значений в зависимости от контекста
Статический - это когла указывакем тип данных имеет несколько значений в зависимости от контекста
Своими корнями он выходит в язык с, который был разработан 1969-1973 годах (в компании Bell Labs, программистом Деннис Ритчи)
В начале 80 годов датский программист Бьерн Страуструп работао в компании Bell Labs, разработал С++. Как расширениее к языку с. Фактичиски в начале С++ дополнял язык С, с некоторыми возможностями ООП. Изначально язык назывался "Си с классами"
С++ является компелируемым языком, а это значит компилятор транслирует исходнвй код на С++ в исполняемый файл, который используется набор машинных инструкций.

### Зачем компилярные файлы
Исходный файл С++ это код, но его не возможно запустить как програму или файл. По этоиу каждый файл скомпилировать в исходный файл.

### Этапы компиляции 
1)препроцессинг - это макро процессор, который преобразовует программу для дальнейщего компилирования, на дальней стадии происходит работа предпроцесорными деерективами. 
Например: процессор добавляет хэдер в код (#include), уберает коментарий 
2)компилятор - обрразовует ассемблерный код. это промежуточный этап между высокоуровневым языком и машинным кодом.
3)ассемблированого - первод кода в машинный код
Обьектный файл это созданный файл промежутачный файл хранящий файл хранящий машный код. Этот кучок машинного кода, который еше не связан с другими кускими машинного кола называется - обьектный кодом. <br>
4) компановка - компановщик (линкер) связыывает все обьектные файлы и статичесике библиотеки в ед импользовнный файл, который могут запустить все. <br>
5) загрузка

## Файлы, которые создаются автоматически при создании проекта

* ConsoleApplication1.sln — файл решения. Это контейнер верхнего уровня, который объединяет один или несколько проектов. В нём хранятся настройки конфигураций (Debug/Release), платформ (x86/x64), ссылки на проекты. Именно этот файл вы открываете двойным щелчком, чтобы загрузить всё решение в Visual Studio.

* ConsoleApplication1.vcxproj — файл проекта C++. В нём записано всё, что нужно для сборки: список всех .cpp и .h файлов, пути к папкам с заголовками и библиотеками, флаги компилятора (например, /std:c++17), настройки линковщика, конфигурации Debug и Release. Это XML-файл, который Visual Studio читает при каждой сборке.

* ConsoleApplication1.vcxproj.filters — этот файл отвечает за группировку файлов в обозревателе решений. Он не влияет на реальное расположение файлов на диске, а только создаёт виртуальные папки (например, "Source Files" для .cpp, "Header Files" для .h, "Resource Files" для ресурсов). Если вы переместите файл в другую виртуальную папку, физически он останется на том же месте.

* ConsoleApplication1.vcxproj.user — хранит пользовательские настройки: параметры командной строки для отладки, рабочий каталог, переменные окружения. Этот файл генерируется индивидуально для каждого разработчика и обычно исключается из системы контроля версий (добавляется в .gitignore).

### Исходные файлы проекта
* ConsoleApplication1.cpp — это главный, а в вашем случае единственный файл с кодом. Он содержит функцию main() — точку входа. В нём вы видите #include <iostream> для работы с вводом-выводом и вывод строки Hello World! в консоль. Все остальные .cpp файлы, которые вы добавите позже, будут содержать реализации других классов и функций.

* pch.h (если используется) — файл предкомпилированного заголовка. В него включают стандартные и редко меняющиеся библиотеки (<iostream>, <vector>, <string>, <algorithm>). При сборке этот файл компилируется один раз, а затем все .cpp файлы используют его готовую версию, что ускоряет компиляцию больших проектов.

* pch.cpp — парный файл для pch.h. Обычно содержит единственную строку #include "pch.h". Он нужен только для того, чтобы механизм предкомпиляции работал корректно. Сам по себе этот файл не содержит полезного кода.

* framework.h — появляется в некоторых шаблонах (например, если вы создаёте проект с поддержкой Windows). Он подключает базовые заголовки Windows SDK, такие как Windows.h, tchar.h и другие. В вашем консольном проекте его скорее всего нет, но в проектах с графическим интерфейсом он почти всегда присутствует.

### Выходные папки 
Debug/ или Release/ — папки, которые создаются в директории проекта после компиляции. В них лежат:

1. .exe — исполняемый файл, который можно запускать.

2. .obj — объектные файлы, полученные после компиляции каждого .cpp файла.

3. .pdb (только в Debug) — файл отладочной информации, нужен для точек останова, просмотра переменных и стека вызовов.

4. .ilk (в Debug) — промежуточный файл для инкрементальной линковки, ускоряет пересборку при небольших изменениях.

В вашем файле есть комментарии на русском языке — это подсказки для начинающих разработчиков. Они не являются кодом и не влияют на работу программы:

#### Блок комментариев внизу содержит советы:

1. В обозревателе решений можно добавлять и удалять файлы.
2. В Team Explorer можно подключиться к Git или другим системам контроля версий.
3. В окне "Выводные данные" видны сообщения сборки.
4. В "Списке ошибок" перечислены ошибки и предупреждения компилятора.
5. Через меню "Проект" можно добавить новый или существующий файл в проект.
6. Чтобы снова открыть проект, нужно выбрать файл решения (.sln).
